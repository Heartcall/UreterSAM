# 不同明度蓝色的光纤本体范围与独立可见末端：规则修订

2026-11-01。依据用户新说明：“蓝色组织较少，光纤前端仍满足光纤形状的不同明度蓝色均纳入光纤本体，确定最终尖端”。这是下一版候选的设计修订；本轮只核查源码与既有日志，没有实现新分割候选、运行新网络、训练或改默认。上轮停止决定与全部失败指标保留。本文件不是已完成实验，也不是数值已冻结的执行配置。

## 1. 这次实际改变什么

目标改为**先识别与可信主体属于同一个可见蓝色管体的完整范围，再检测其真实外轮廓的远端结束**。同一轮廓内的浅蓝—深蓝—浅蓝过渡不产生新的实例或端点。主体前方的低神经概率不是排除理由；有本帧连续蓝色和形状证据时，原P_fiber<0.1也可以成为候选。

“蓝色组织少”是用户提供的场景先验，尚未量化成可靠误认率。接纳条件是当前主体身份、连续图像证据与合理外形共同成立；不是全图任意蓝像素都属于光纤。已有网络正确光纤中的低饱和高光不因缺蓝被删除；新扩展中颜色无法辨认的像素保持未知，不能靠理想管体填满。

## 2. 旧代码和日志已证实的限制

- `chroma()`已计算RGB/(R+G+B)，理想的共同亮度缩放不会改变该色度。因此不能把旧失败全部归因于“没允许暗蓝”。阴影、通道不同比例变化、噪声与过曝仍可能改变色度，旧单个种子中位数/MAD球也不等同于整个蓝色外观族。
- 种子必须至少3/5截面同时通过两侧绝对RGB对比门槛。固定1209只有2/5，内部色度支持却充分，搜索在生长前被挡住。它证实种子资格失败；不能据此证明所有单侧弱边都是光纤或降低阈值即可解决。
- `section()`在两侧分别选最大RGB变化，并未显式判断该变化是“蓝色内部亮暗过渡”还是“蓝色—周围组织外边界”。内部强反光/色带可能竞争边缘，这是代码机制支持的待验证假设，没有逐像素归因比例。
- `tip()`仅在`accepted.any()`后调用。video_1的722帧均有合格种子、没有新增，全部没有独立末端检查；video_2有431帧至少一个种子合格但没有检查，不能据此说这些帧存在真实可定位尖端。70静态中此类50帧、132图像12帧。数字由原日志重算，不是新实验性能。
- 上轮候选图像参考Precision仅18.53%，故身份和边界扩张仍必须审计；不能用“蓝组织少”直接推翻已观察到的误检。

完整计数保存于本轮只读诊断summary；seed失败计数以组件为单位，一帧可有多组件，不冒充失败帧率。

## 3. 最小新候选：蓝色本体外边界与端帽

只引入一个新候选，不扫颜色强度、Gamma或多种融合权重。

1. **主体与远端方向。** 沿用原网络高置信光纤核心作为身份锚点，但把轴与两条长侧边的可见片段联合评价。视野边缘裁切的一侧记作未观测，不伪造成一条低对比边再一票否决。当前可见边、蓝色区域相对背景、宽度/锥度须有组合支持；仅神经高P或仅单条边不直接建立身份。方向由本帧入口/侧边收敛确定，T1只辅助排除跳变；方向歧义时不给唯一远端。
2. **不同明度归为同一蓝色族。** 保留同帧局部归一化色度与背景对比，分别记录亮度、蓝色色度和颜色可靠性；从“与单个杆体颜色均值距离小”改为“兼容主体的蓝色族且区别于当前侧背景”的软证据。初始身份锚点固定，不能把生长接纳像素反复更新成新模板导致漂移。具体色度兼容/噪声评分及数值界限必须在新实验前一次性登记；不依据1209选参数、不从验证视频拟合共享颜色模板。
3. **搜索外边界。** 横向检查蓝色支持在两侧是否结束并转为局部背景；管体内部亮度梯度仅作光度变化，不直接选为外边界。将本帧不同位置的可见边缘片段联合约束近似两长直边和小锥角，允许局部弱边，避免逐截面要求两侧都达到固定绝对亮度差。这是边缘语义和部分可见建模的改变，不是把旧0.04阈值调低。
4. **纳入整段当前可见本体。** 仅沿当前RGB支持、从可信主体可达且位于合理外边界内的区域搜索；不因浅蓝变深蓝提前停下。拟合外形只限定候选位置，不将理想多边形填成光纤。未知/遮挡不桥接，邻近不连通蓝区不自动吸附，原结石先作为屏障并单列冲突。偏离轴向、宽度突增、组织泄漏或身份歧义时拒绝新增，保留原输出。
5. **独立末端检测。** 每个有可信可见主体的帧都尝试，不要求先新增像素。沿已确认远端方向，结合本体两侧外边界的圆钝收拢、端部RGB边界、端外可见背景及进一步延伸证据定位。内部颜色变化后若侧边/蓝色本体继续，就继续搜索。尖端是可见圆钝端帽的最远端位置及不确定范围，不是两长直线无限延长的交点，也不是最远蓝噪点。
6. **明确状态。** 输出`visible_end_supported`（仅当前证据支持的候选坐标/不确定度）、`occlusion_suspected`、`out_of_view`、`unknown`；遮挡边缘不冒称真实端帽。深蓝后若接低饱和高光，不能把“蓝消失”当末端：需继续检查原概率与独立RGB外轮廓。没有独立末端像素/位置参考，坐标仍是未验证预测。

允许同一实例可见掩膜不连通；本轮新增生长只处理当前可见连续段，已有其他片段保护，不填隐藏连接。前述“全部纳入”作用于有证据的当前可见管体，不暗示几何恢复遮挡形状。

## 4. 实施顺序和可证伪对照

先冻结一个数值执行协议，明确部分边缘资格、蓝色族评分、外边界拟合、端帽支持与拒绝规则、原像素保护、预算和身份记录。旧实现不修改，新工具/配置另命名。

最小三臂：原raw2、已冻结旧connected_rgb、新“蓝色本体外边界+独立端帽”候选。新臂只输出候选层和独立末端元数据，实际掩膜暂不改；保留仅背景并入的虚拟指标，原正确光纤/结石删除须为0。T1复用既有冻结定义，仅方向/截短提示，不新增一个T1像素变体。

**每个实际实现的臂均须在video_1的722帧和video_2的1972帧上完整运行，静态不达标也不免测。** 若三臂重新实测则6个独立进程、8082正式帧；共享202静态原推理，另记预热/实际forward，不用缓存替代正式完整回放。

原70/132、原29/新增41/最近5、43/27病例、68/64来源、25/107曝光及全部争议图保持。报告两类别Dice/Precision/Recall/边界F、TP/FP/FN绝对变化、原P<0.1和低亮FN候选覆盖、无种子损失、误种子/外溢/冲突、端部四状态、P50/P95、CPU/GPU与含导出吞吐。无语义真值帧不能称全片准确率；无独立尖端真值不能称定位准确率提升。

沿用新增候选Precision各≥98%、70/132/固定1209低Lab FN虚拟减少各≥10%、原29与raw2/classwise质量不退化、原正确像素零删除、额外p95≤5ms及总p95满足源帧预算。不能根据新结果改门槛。关键失败则保留负结果、停止这一配置，不追加阈值扫描、训练或直接部署。

本修订提出的新可证伪问题是：从绝对RGB强边改为管体蓝色—背景外边界及部分可见边缘联合支持，能否既通过暗段种子/范围检查，又避免132图像中的误扩张？独立端帽检查能否在无新增帧产生正确、可审查的当前证据状态？第二问在缺少尖端真值时只做覆盖、错误状态案例和成本诊断，不作准确率结论。
