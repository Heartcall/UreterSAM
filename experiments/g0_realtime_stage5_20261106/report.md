# G0 第五轮独立优化实验（2026-11-06）

> 状态更新：用户于 2026-11-06 要求取消 Windows x64 DLL 优化。v5 运行入口已恢复为 v4 NumPy 的直接别名，构建和加载入口停用；下文性能与核验结论仅为撤回前的历史结果。旧结果与原源码归档保留，新一轮见 stage6 独立实验。

本轮完成 S2 候选域裁剪和严格原生算术融合：同轮合并串行吞吐 **11.07 → 12.84 FPS（+16.0%）**，CPU 后处理 **55.57 → 46.12 ms/帧（−17.0%）**，2,694 帧的 S2/G0 掩膜零像素变化，53 项检查全部通过。仍未达到 30 FPS。

原始 `final/` 全程不读取、不运行、不修改。所有新增代码位于本实验目录，模型、原始工具、配置及前四轮代码保持冻结。新增编译二进制位于独立运行目录，是本轮引入的主要维护与移植成本。

## 改动与等价边界

1. 将 S2 大图颜色判断、证据评分和坐标投影合并到独立的 Windows x64 原生模块中，减少 NumPy 临时数组及多遍读写。小样本、浮点 RGB 探针及 float64 种子继续调用原来的函数。
2. S2 从原身体像素、原分位数和原侧向宽度计算保守矩形，只在矩形内计算候选域。保持原绝对像素坐标、乘加顺序和边界比较；利用实际坐标矩阵的逆，外加 2 像素保护。
3. 完整梯度、完整 8 邻域传播图、域外原身体像素、端帽外围、拟合迭代、时序状态和 G0 第四轮实现保持原规则。未裁剪梯度、连通图或距离变换。

模型、FP32 精度、输入尺寸、每帧两次网络前向、阈值、无回退政策和帧顺序不变。没有跳帧或跨帧复用当前图像证据。

原生模块使用已有 MSVC 编译器和 `/fp:strict`，固定算术顺序，显式使用标量 SSE2 平方根。编译策略的含义参见 [Microsoft 浮点行为文档](https://learn.microsoft.com/en-us/cpp/build/reference/fp-specify-floating-point-behavior?view=msvc-170)。编译选项不是等价性的证明，数值与掩膜仍须实测。

当前系统缺少 Windows SDK/UCRT 头文件；没有安装任何包或 SDK。最终 DLL 不使用 CRT、堆分配、入口函数或外部导入，构建身份及导入表保存在 `runs/g0_realtime_stage5_20261106/native_final/`。前期失败构建日志也保留。这是一项 Windows x64 实验依赖，移植或重编译后必须重新验证，不能仅凭源码相同推定等价。

## 测量设计

同轮比较 v4-serial 与 v5-serial：video_1 完整 722 帧，video_2 完整 1,972 帧。每个案例独立进程，12 次预热后重置运行状态，固定 CPU 库为单线程。video_1 先 v4 后 v5，video_2 反序。两组均使用同一套网络同步与 CUDA 事件计时，且都归档相同的源码和原生二进制。

设备为 NVIDIA GeForce RTX 4070 Ti；现有 Python 3.11 环境使用 PyTorch 2.11.0+cu128、NumPy 2.4.6、OpenCV 4.14.0。具体 CPU 身份、库线程池、可用内存、视频和检查点哈希均保存在各案例的 `identity.json`。

吞吐率为完成全部输出的实际计时墙钟：包含解码、同步网络推理、CPU 后处理、轻量核查和审计掩膜内存复制；大批量 PNG/日志导出在计时区外。延迟从帧获准进入处理至结果完成。相机采集、显示、编码、启动和进入处理前排队不在此范围内；不能当成完整实时应用性能。未测第五轮流水线。

每个视频只进行一次完整配对。本轮不报告统计置信区间，也不把此前轮次不同负载下的绝对 FPS 拼接为累计加速倍数。网络未优化，网络计时变化属于测量条件波动；CPU 后处理的同轮变化是归因更直接的证据。

## 微基准与核验

40 次交替测量、5 次预热的微基准见 `runs/g0_realtime_stage5_20261106/microbench/results.json`。在合成图和随机图上，证据评分约快 1.17–1.96 倍，颜色判断约快 2.27–5.78 倍，完整坐标投影约快 5.83 倍。这些是局部运算结果，不能充当整条流程的加速率。

检查要求：Raw2 和网络概率哈希完全一致；S2/G0 掩膜逐像素一致；G0 决策一致、几何参数按原比较器 1e-9 容差；历史 S2 一致；结石标签受保护；模型、视频、源码与 DLL 身份一致。另用固定用例对大图评分、颜色门、完整候选域和坐标投影作精确比较，覆盖小探针回退、方向变化、空目标、结石、面积预算回退与状态重置。

## 最终核验

- 四组案例共执行 5,388 个正式帧，另有 48 个预热帧；每组正式网络前向严格为每帧每模型一次。
- 两个 v4/v5 对照和两个 v4/上一轮历史对照全部通过：S2/G0 零像素差异、Raw2/概率/帧身份哈希一致、G0 决策与几何满足原比较器要求。
- 每组 G0 成功应用 2,654 帧，40 帧原有不可用原因保持一致：35 帧尖端到达或越过侧边交点、2 帧无可信主体、3 帧可信主体歧义。S2 接受端帽共 1,372 帧。
- 结石标签零变化；模型状态一致。当前全部 **218 个源码/配置文件** 与四份归档一致，其中前四轮的 **208 个文件** 均与上一轮记录相同。
- 四份 `source_snapshot.zip` SHA256 相同：`dc7755d11bef9dae5eb3fdc223430403d8b7fd9ee38feb6fd882347a5ca62366`。归档包含 C++、构建/测量脚本和实际 DLL，逐个检查了成员哈希。
- DLL SHA256：`f34a877dac22650cf7623d4ea932c55b3c8aee43e785305bbe6a84380ddde0fd`，与构建记录及全部案例一致；导入表无外部依赖。
- 53 项单元/语义检查通过；剖析重放的 23 帧另行与上一轮比较，仍零像素差异。

精度结论仅指这些视频和固定测试上的输出等价；本轮没有新增人工真值，不能据此宣称医学分割准确率提升或覆盖未知视频。

## 剩余瓶颈与下一步

优化后 S2 仍占正式 CPU 后处理 **82.54%**。在同一环境重新对 23 个选定帧剖析，平均 CPU 后处理约 53 ms，含剖析开销；以下为累计时间，存在包含关系，不能相加：

| 范围 | 平均每个剖析帧 ms | 关系 |
| --- | ---: | --- |
| S2 扩展 `expand` | 17.59 | 包含端帽等子调用 |
| 初始蓝色连通生长 `grow` | 12.32 | 包含约 5.4 ms 的种子提取 |
| S2 端帽 `fit_cap` | 7.39 | 23 帧中实际调用 17 次；每次约 10.00 ms |
| 侧边稳健模型 `robust_model` | 3.45 | 包含样条评估和求解 |
| 完整梯度 | 2.51 | 本轮保持全图 |
| 分组剖面 | 2.25 | 端帽路径中的子调用 |

全局 796 次 `nonzero` 累计约 4.19 ms/帧，样条评估累计约 2.10 ms/帧，所有 `lstsq` 累计约 1.44 ms/帧。这些时间分散在多个父调用中，也不能与上表相加。

后续优先级建议：

1. **先融合蓝色初始生长中的域判断与颜色筛选。** 当前 `grow` 仍生成整幅投影、掩膜，再压缩为 `frame[region]` 并散射回整图。可沿用本轮原生后端减少这些中间数组，保持核心像素、4 连通根选择、结石处理与全图连通结果不变。该函数自身耗时约 4.80 ms/帧是这部分的近似上限，不能把其 12.32 ms 累计时间全部当成可消除成本。
2. **按调用作用域复用不变身体的坐标与统计。** 先定位重复扫描同一掩膜的位置，再复用行序一致的非零坐标、投影和计数；掩膜修改后立即失效，不能仅按对象地址缓存。仍用全视频输出和时序状态逐帧比较验收。
3. **测试 v5 的有界双阶段流水线，并控制测量波动。** 已有 v2/v3 流水线结果不能外推到 v5；需同时保留同轮 v4/v5 串行对照，记录 GPU 时钟和竞争进程，按正反顺序重复配对。仅检测当前设备负载不会解决跨轮计时差异。

以本轮均值估算，网络 29.42 ms、CPU 后处理 46.12 ms；完全重叠且无争用时，CPU 阶段仍将吞吐限制在约 **21.68 FPS**。这是条件性容量估算，不是实测流水线结果，帧延迟也不会缩短为两阶段耗时的最大值。若以 30 FPS 为目标，CPU 阶段至少还需下降约 **27.7%** 到 33.33 ms 以下；实际还要留解码、审计、调度和负载波动余量。当前网络 P95 已超过 33.33 ms，后续还需分析推理波动。

暂不优先替换小矩阵求解器、减少拟合次数或裁掉全图连通/梯度：前者在本轮剖析里收益上限小，后两者会触及现有输出规则。原生融合与 S2 裁剪本轮一起测试，尚无分别启用的全视频消融，不能精确划分各自贡献。

保留 v5 作为已验证的独立实验候选；生产 `final/` 尚未迁移。移植成本主要是新的 Windows x64 DLL，v4 纯 Python 参考可继续独立运行；v5 对小探针和非支持种子的回退不代表 DLL 缺失时会自动降级。
