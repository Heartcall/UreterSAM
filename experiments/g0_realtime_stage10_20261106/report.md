# G0 第十轮：种子组件复用与剖面统计批处理

**结论：本轮组合方案暂不采用。** 固定输入 CPU 四轮平均减少 3.70%，但两段完整流水合并吞吐从 17.7837 降至 17.3318 FPS（-2.54%），处理延迟 P95 从 130.6037 增至 141.5314 ms。2,694 帧 S2/G0 掩膜逐像素一致，正确性核验通过；当前没有满足实时目标的性能收益证据，保留实验和失败结果，不替换任何入口。

2026-11-06。目标沿用用户明确的实时内镜 30 FPS 输入、采集到叠加显示低于 100 ms。本轮验证两项保持结果的 CPU 计算优化，未启用跳帧、历史时间门限变更或过期显示策略。

## 变更与数值合同

参考仍为已验证的 v7 NumPy Runtime，未采用第九轮区域颜色索引候选。只新增独立实验，不读取、不运行、不修改 `final/`；前九轮、原模型/配置和恢复后的 v4 入口保持原样，不启用自定义 DLL，不安装依赖。

1. **种子组件复用。** 原 QualifiedSeedObserver 先做一次 4 连通组件标记，之后按面积/标签顺序为每个候选复制 isolated mask，再由 AggressiveVariant 对同一组件重新做 4 连通标记。候选直接复用外层标签、统计和面积门限，删除重复的隔离掩膜和组件遍历；从 OpenCV 给出的组件包围框中按行优先取坐标，加回整数偏移。后续 PCA 的输入、采样点顺序、颜色/背景判定、截面、侧线拟合、弱历史、候选排序和歧义规则不变。父层单组件局部 label=1 的记录在外层照旧映射回原组件标签，保留异常预算分支。
2. **剖面极值批处理。** grouped_profiles 仍使用同一非零点、同一坐标投影、相同分箱与稳定排序。批量计算每个箱的最小/最大值，并选取其第一个原始位置，保留 np.argmin/argmax 的并列选择规则。每箱均值仍调用原顺序的 np.mean，不用另一个加法归约替代，以避免细微浮点差异影响后续拟合。只绑定实例自己的 S2 side/fit_cap globals，不修改全局 NumPy 或原模块。空输入保留原异常；非有限投影或异常步长回到原函数。

完整梯度、图传播、G0 尖端与几何重建、每帧两个网络各一次 FP32/batch1 推理、原时间戳和状态更新均保持。G0 继续通过原有当前帧缓存复用 S2 种子；未跨帧缓存种子，也没有改历史过期规则。

## 检查与固定输入筛选

64 项相关检查加 3 项剖面检查通过，分两批执行。新增检查覆盖孔洞、边缘、对角接触、概率与结石保护、面积并列、32/33 个候选预算、内层组件预算、弱历史/年龄、缓存与 reset，以及稀疏/单点/密集剖面、轴方向、分箱步长、边距和实例隔离。种子完整记录和合成剖面均按精确数组值比较；功能运行比较掩膜和不含耗时的几何。初次检查曾误把实际耗时字段也当作相等项；已改用原 geometry_record 排除耗时后通过，未改算法迎合检查。

固定输入从原 video_2 的 23 个重点帧重新执行双网络，RGB/Raw2/光纤概率哈希逐项核对第八轮完整结果；网络结果常驻内存后，三组 Runtime 独立状态，四轮轮换/反序，各轮 12 次预热后重置，沿用原帧时间戳。只计 CPU 后处理，不含模型和视频输入。

第一段改善、第二段变差；合并后 CPU 平均变慢 2.53%，网络服务平均变慢 6.95%，延迟 P95 增加 10.9277 ms。候选超过 100 ms 的总帧数略少，但其尾部和最大延迟更差，不能只选超时比例这一项宣称改善。两个方案均未满足 100 ms，且尚未计采集和显示。

### 输出与身份核验

四项独立 PNG 比较全部通过：每段视频候选对本轮参考，以及本轮参考对第八轮同方案。S2 和 G0 改变像素、改变帧均为零；RGB、Raw2 和光纤概率哈希精确一致，G0 决策与几何在绝对容差 1e-9 内一致。每帧网络各一次 forward，原帧序、时间戳、历史 S2、结石像素和模型状态核验通过。

每方案 G0 应用 2,654 帧，40 帧按原规则不可用；原有种子/证据/色度复用和空间计数在两方案间一致。新方案全视频 S2 种子外层标记 2,694 次，省去内层重复组件标记 3,053 次；坐标提取比较域从 488,480,000 减至 26,804,914 像素（约 5.49%）。这些是确实减少的局部工作量，不能自动换算成完整加速。

完整共执行 5,388 帧另有 48 次预热，261 个源码/配置文件与当前文件和四份归档均匹配；四份源码归档 SHA256 一致。前九轮的 247 个冻结源码/配置文件未变，自定义 DLL 关闭。归档不包括 `final/` 或 C++ / DLL 文件。

FPS 为总帧数 / 总墙钟，含解码、同步网络、顺序后处理、轻量审计及位打包；PNG/JSONL 批量导出在计时外。单帧延迟从取得处理额度、开始解码到后处理结果完成，不含进入处理前积压、实际采集、叠加或显示；不能当作采集到显示延迟。网络服务重叠比例来自主机区间，不是 GPU 占用率。每视频每方案只测一次，P95/P99 是帧级分布，不是重复实验置信区间。

## 剩余瓶颈与下一步分析

完整计时和 PNG 核验完成后，另在候选实际流水中剖析 23 个重点帧的主线程后处理；12 次预热后重置状态，仅剖析 23 次 Runtime.run，输出再与第八轮同组输入重读 PNG 比较通过。剖析期间有额外开销，以下只作定位；不能与不同轮剖析耗时直接相减当作加速，也不能把嵌套累计值相加。

| 当前候选剖析入口 | 每测量帧累计平均 / ms |
|---|---:|
| CPU 完整后处理 | 63.85 |
| S2 整体 | 53.08 |
| RGB grow（含种子和颜色） | 17.47 |
| S2 expand（含端帽） | 17.95 |
| G0 整体 | 10.50 |
| 区域颜色 region_color | 6.37 |
| 种子 qualified_seeds | 5.84 |
| 40 次 grouped_profiles 总计 / 23 帧 | 2.80 |

这里的数值以 pstats 为准；种子和剖面已经只占完整路径的一部分。即使继续压缩这一小部分，也不能把完整 CPU 从本轮 55–57 ms 降至约 30 ms。

下一轮应优先做以下有界工作，不继续堆叠亚毫秒局部变更：

1. **建立 NN 与 CPU 分阶段的低开销关联计时。** 同帧分开记录输入准备、实际两个 forward、传输/同步、grow、证据与梯度、连通传播、fit_cap、G0，再关联并发区间和延迟尾部。将“同一输入计算成本”与“流水运行时等待/资源竞争”分开测，避免把其中任一项当作原因。先查明固定输入收益为何不能稳定体现在流水中，当前没有证据指认具体争用来源。
2. **优先定位 S2 grow/expand。** 尤其是原生像素证据、完整梯度、连通与端帽共享准备，保持输出语义的前提下减少重复数组遍历和临时数组。对只改变坐标/局部扫描的方案继续执行完整路径验证；不能截断可能改变连通性的图域，也不通过放宽阈值、减少拟合或历史补像素换速度。
3. **仍需真实 30 FPS 测量壳。** 连续采集的原始时间、帧号、处理和呈现都要关联；摄像头到显示目标尚未实测。若研究最新帧/最新结果槽，按第九轮已识别的时序有效期问题独立验证，不能把跳帧当成此轮精确计算优化的自然延伸。
4. **采用门槛按用户目标。** 先要求掩膜/帧对应正确，再要求完整延迟尾部和有效更新率改善。以当前候选 CPU 平均估算，压到 30 ms 还需约减少 47.49%；这只是工程预算差距，不是下一轮收益承诺。仅局部加速、平均 FPS 上升或正确性通过都不足以批准进入实时部署。
