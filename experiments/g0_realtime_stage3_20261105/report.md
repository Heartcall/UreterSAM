# G0 第三轮优化分析

日期：2026-11-05。本轮代码和结果均位于独立实验目录；`final/` 未读取、未运行、未修改。原工程及前两轮实验保持冻结，没有安装或升级依赖。

**本轮完成了进一步等价加速：串行综合 9.51 → 10.23 FPS，流水综合 13.47 → 14.62 FPS；仍未达到 30 FPS。** 以下均为本轮同一计时入口重新运行的新旧对照，不直接引用上一轮的 FPS 作为分母。

|---|---:|---:|---:|---:|---:|
| 第二轮串行 v2 | 9.79 | 9.42 | 9.51 | 104.87 | 125.40 |

串行综合吞吐提升 **7.52%**，两视频分别提升 **13.50% / 5.56%**；CPU 后处理平均 **67.50 → 61.39 ms，下降 9.06%**。流水综合提升 **8.54%**，但第一段下降 **1.20%**、第二段提升 **11.81%**，不能据一次全量测量宣称稳定收益。流水 CPU 后处理平均 **73.92 → 68.08 ms**。

**建议：保留 v3 串行作为低延迟实验候选；v3 流水保留为吞吐实验候选，先重复测试，再考虑替换已有流水方案。** v3 流水相对 v3 串行吞吐更高，但平均延迟增加 38.60 ms、P95 增加 46.89 ms。本轮没有替换任何默认运行入口。

四组各完整处理 2694 帧，共 **10776 帧**，两网络各实际前向 10776 次，另有 96 次预热双网络调用。十项独立全量比较全部通过：Raw2、光纤概率哈希一致；S2/G0 重读 PNG 均为 **0 改变像素**；记录的 G0 可用状态、原因、尖端选择及几何满足合同；结石像素不变。各组均为 2654 帧正常重建、40 帧不可用（35 尖端达到/超过交点、2 无可信主体、3 主体歧义），S2 cap 接受数均为 1372。

**44 项检查通过**；模型运行前后状态、视频/权重身份及 202 个源码/配置文件身份不变；前一轮的 196 个源文件也重新核对无改动。每组保存源码归档和环境身份。机器可读汇总见本目录 `results.json`，原始数据见 `runs/g0_realtime_stage3_20261105/full/`。

## 为什么做这一轮

第二轮串行 CPU 后处理仍为约 72 ms，流水吞吐接近这一 CPU 阶段的平均服务能力。新版剖析中的 S2 `expand`、连接颜色区域 `grow` 和梯度是主要剩余路径。这些函数包含嵌套调用，累计时间不能相加。

此次选择已有 NumPy/OpenCV 原语的组合改写，优先减少三通道归约、重复颜色归一化和标签筛选开销。当前环境未安装 CuPy、Numba、llvmlite 或 Cython；本轮不引入新的编译环境，也没有改为半精度、降采样或跳帧。

## 采用和放弃的候选

1. **三通道定长运算**：色度的 RGB 求和、颜色证据中的三元素范数/点乘，使用明确的三项计算。在现有 NumPy 2.4.6 环境检查结果逐值一致。G0 原来的矩阵点乘路径仍保留，不擅自改成另一种归约。
2. **直接复用归一化颜色**：S2 的证据和连接区域颜色判据，直接使用已计算的 RGB 色度及噪声，避免在筛选后再次转换和归一化同一批像素。分数、阈值和判断顺序的语义保留；小型终端探针保留原函数，因为连续分数参与尖端判定。
3. **梯度临时数组复用**：保留原图 float32 归一化、原 `Sobel` 算子及默认边界；将平方、加法和平方根写入自身临时数组，减少分配，并替换固定三通道求和。输入图像本身不改动。
4. **8 邻域标签查表**：仍用原 OpenCV 8 邻域连通标记，再直接标记包含 anchor 的标签并映射回像素，代替 `unique` 后的 `isin`。背景标签 0 强制排除，多个 anchor 及多个可达分量均保留。
5. **未采用：4 邻域 bincount 改写**。其微基准仅约 1% 收益，缺乏足够证据支持接入运行路径。实验函数及测试保留作负结果记录，正式 Runtime 继续调用原 4 邻域实现。

实现文件：`pixels.py`；私有绑定：`runtime.py`。只修改私有加载的模块及当前运行实例，未对原模块做全局替换。沿用第二轮的同帧缓存、弱历史回退、有界流水及诊断简化政策。

三项运算的等价性不推广到任意长度归约、任意库版本或任意数据布局。NumPy 文档指出浮点求和的精度与归约轴、布局等条件有关，因此升级 NumPy 或改动精度后必须重新验收。[NumPy 2.4 求和文档](https://numpy.org/doc/2.4/reference/generated/numpy.sum.html)

## 新版剩余热点及下一步

全量完成后，使用单独驱动仅剖析 **23 个重点帧的 CPU 后处理调用**，排除了导入、12 次预热、网络、解码及导出。记录在 `profile_v3/post_cpu.txt`、`hotspots.json`；驱动脚本及其 SHA256 单独保存。该回放也通过输出精确比较。剖析包含额外开销，下面是定位数据，不与正式耗时直接混算，也不与之前包含预热的剖析直接算加速比。

| 路径 | 每帧累计 ms | 解释 |
|---|---:|---|
| S2 expand | 26.28 | 含 cap、梯度、证据等子调用 |
| ConnectedBlue grow | 16.61 | 含主体识别约 5.62 ms |
| S2 fit_cap | 10.05 | 17 次调用摊到 23 帧，包含在 expand 中 |
| G0 lazy_tip | 8.38 | 自身约 5.19 ms，仍需候选域、坐标、筛选与排序 |
| G0 fit_geometry | 5.32 | 包含侧边观测与拟合 |
| 分组 profiles | 4.29 | 40 次调用的总摊销，分布于不同阶段 |
| native_gradient | 3.23 | 已优化，收益空间相对缩小 |
| 全部 lstsq | 1.51 | 即使消除此调用的全部时间，单独收益仍有限 |

以上数值存在嵌套，**不可相加**。观察到 81 次坐标网格构造，合计约 2.03 ms/帧，750 次 `nonzero` 合计约 3.75 ms/帧；这支持进一步减少全图扫描及临时数组，而不是仅把某一个小型拟合求解器替换掉。

下一步按收益空间和风险排序：

1. **先验证坐标域复用及保守 ROI**。同一形状的只读像素网格可复用；S2 扩张和 G0 尖端候选在局部域内计算坐标/判据，再按原坐标映射。必须保留完整可达域、3×3 支持所需的 1 像素邻域，以及 Sobel/距离变换所需边界；不能把裁剪边界当成原图边界。网格复用单独上限约是本次剖析的 2 ms/帧，不能将其宣传成 30 FPS 方案。ROI 的更多收益尚未测得。
2. **再对 grow、expand、lazy_tip 的多次数组遍历做整体融合**。这三条路径覆盖主要剩余像素运算，应一起考虑颜色、投影、域判断、候选筛选、梯度和标签使用，而不是仅继续优化色度或某一次线性求解。先做含所有准备/回传成本的原型，保持原 dtype、排序、阈值、结石保护和时序回退；在目前环境中，这可能需要单列原生编译或 GPU 实验，并不是本轮已经实现的能力。
3. **GPU 版本必须与网络一起测**。原网络入口的 `experts.sync()` 调用 `torch.cuda.synchronize(self.device)`；官方定义是等待该设备所有流中的 kernel 完成。[PyTorch 2.11 同步文档](https://docs.pytorch.org/docs/2.11/generated/torch.cuda.synchronize.html) 据此推断，将零散后处理算子放回 GPU，可能让它与下一帧网络争用，并被原同步串行化；不能把 CPU 微基准的收益或单 GPU 算子耗时直接套进现有流水。应在独立原型里同时测完整传输、同步、队列延迟与最终输出，再决定是否采用。

当前 v3 流水 CPU 后处理平均 **68.08 ms**，对应忽略其他成本时约 **14.69 FPS** 的平均服务能力，接近观测的 14.62 FPS。若目标是稳定 30 FPS，CPU 阶段需从 68.08 压到约 33.33 ms，至少再下降约 **51.0%**，网络与长尾仍须达标。单帧低延迟要求整个串行路径也符合预算，不能只看流水吞吐。本轮结果支持继续优化，但不支持承诺下一项局部改动就能达到 30 FPS。

## 全量实验方法与限制

预先固定四组：第二轮串行、第三轮串行、第二轮流水、第三轮流水。每组完整运行视频 1 的 722 帧及视频 2 的 1972 帧；视频 2 内新旧运行次序反转，以减轻简单顺序偏差。每组独立进程，全部依次运行，每个实际网络线程预热 12 次，随后重置后处理状态。FP32、batch=1、原双网络、PIL 256 输入及源 400×400 图像不变。

使用与第二轮相同的计时方法：实际输出帧数除以总墙钟时间；包含解码、同步网络、CPU 后处理、轻量哈希及 RAM 掩膜快照，PNG/日志批量导出在计时之后。平均和 P95 延迟从获得接纳名额、开始解码计至结果可用；流水模式最多同时接纳两帧，按原顺序更新 CPU 状态，不丢帧。

不计实时摄像头、显示、编码或获得接纳名额之前的背压等待；结果不能解释为摄像头到显示延迟。实际输入速度持续超过处理能力且不允许丢帧时，积压不会因队列有界而消失。本轮每视频每方案仅一次全量测量，帧级 P95 不等于重复运行的置信区间；频率和系统调度仍可能造成波动，应以本轮同时重测的基线比较。

独立比较完整 Raw2、光纤概率哈希及重读 S2/G0 PNG，几何绝对误差上限为 1e-9，同时核对原历史 S2、两网络实际前向次数、结石像素、输入源、模型状态、源码身份和在途帧数。第二轮基线另与其历史完整结果核对。等价性只覆盖已测回放及专项输入，不是新数据的准确率验证。
