**48 项检查通过**；模型运行前后状态及 208 个源码/配置文件身份不变。前三轮对应的源文件清单也已重新核对。机器可读汇总见 `results.json`，原始证据保存在 `runs/g0_realtime_stage4_20261105/full/`。原工程默认入口未替换。

本轮网络函数未变，网络耗时约 14 ms，上轮约 34 ms；其他运行条件对跨轮速度有影响，原因没有由本实验单独验证。因此，8.95% 的加速比以本轮重测 v3 为基线，而不把上轮 10.23 FPS 与本轮 13.50 FPS 的全部差额归因于新代码。

## 实际改变

`spatial.py` 提供两个机制，`runtime.py` 只绑定到当前实例和私有加载的代码。

- **只读绝对坐标网格**：按形状和 dtype 缓存，最多保留四组。S2 grow、expand、cap 和 G0 tip 复用同一坐标值，禁止修改；不缓存图像内容、候选或历史结果。重置清空统计与时序状态，已预热的只读网格继续保留。
- **完整候选域的保守外包框**：只在该框中计算 G0 尖端的坐标投影及域判据。保留完整蓝色证据图和原图坐标，原排序、后续探针、阈值、可用状态及回退不变。

没有裁剪 S2 连通域、梯度或距离变换。没有缩小网络输入、改变精度、跳帧或减少双网络前向。

## ROI 为什么不会主动截断尖端

原搜索域在轴向区间 `a ≤ t ≤ b` 中，满足

`|v| ≤ max(0, (tV − t) tan(α)) + margin`。

取整个区间两个端点上的最大半宽，并与 0 比较，得到覆盖该域的矩形。用实际轴/法向矩阵的逆，将四个角变回原图坐标，计算整数外包框，再加 2 像素保护。矩阵条件不可靠或边界不能计算时回退原完整搜索。

`b` 仍是原来的搜索终点，**不在两直线交点处截断**。交点之后，原判据仍允许在 margin 宽度内寻找颜色证据，越过交点的不可用结论必须保留。

3×3 蓝色支持计数额外读取一圈真实原图邻域；只有原图实际边界才使用原来的零填充。候选坐标保持全图绝对值，逐点浮点表达式不改成局部原点表达式；候选的行列顺序及原优先级不变。输出诊断域、部分已检查候选图仍映射回完整尺寸。

这里的等价性依赖固定配置和当前环境的实际验收，不能推广为任意浮点坐标、任意库版本的普遍证明。升级环境或改变配置后应重新比较。

## 预检与消融

合成场景的 G0 尖端搜索微基准，CPU/OpenCV/BLAS 线程均为 1，色度已按实际 S2→G0 路径预热；每组预热 5 次，随后新旧交替顺序各测 40 次：

| 方案 | 中位耗时 ms | P95 ms |
|---|---:|---:|
| v3 原搜索 | 6.720 | 7.510 |
| 仅网格复用 | 6.329 | 7.266 |
| 网格 + 完整 ROI | 1.413 | 1.679 |

该场景 ROI 为全图面积的 6.74%，主要收益来自缩小候选坐标计算范围，而不是单独缓存网格。这是单函数、单场景预检，不是完整视频 FPS；没有据此承诺 30 FPS。原始记录在 `runs/g0_realtime_stage4_20261105/microbench/results.json`。

23 个重点帧另与上一轮输出精确比较通过。专项加原有检查共 **48 项通过**。新检查覆盖缓存只读性、容量和实例隔离、160 组不同轴向及宽度条件的完整域覆盖、真实图像边缘、交点之后、无候选、无可用终端、病态矩阵回退，以及有状态断裂/结石/缺失/重置。合成验证逐值比较完整搜索域、部分资格图和尖端元数据，不只检查最终赢家。

## 测量与验收

本轮完整对照仅为 v3 串行 / v4 串行。每组运行视频 1 的 722 帧和视频 2 的 1972 帧；视频 2 的新旧执行顺序反转。每组独立进程、单线程 CPU 库，实际网络线程预热 12 次后重置时序状态；保留 FP32、batch=1、原双网络、PIL 256 输入及 400×400 原图。

FPS 使用总输出帧数 / 总测量墙钟时间。包含解码、同步网络、CPU 后处理、轻量哈希和内存掩膜快照，批量 PNG/日志导出在计时之后。单帧延迟从开始接纳/解码至结果可用。不计摄像头、显示、编码及接纳之前的等待，不能称作摄像头到显示延迟。

核对完整 Raw2、光纤概率哈希及重读 S2/G0 PNG；记录的 G0 决策一致，几何误差不超过 1e-9；同时检查历史 S2、结石像素、模型状态、输入身份、源码、两网络实际前向次数及完整帧序。v3 重测结果另与第三轮历史全量结果比较。

每视频每方案一次完整运行，帧级 P95 不是重复运行的置信区间。网络函数未变，系统调度和频率仍会影响实际时间，因此只对本轮重测基线计算加速比。输出等价检查也不是新数据上的分割准确率或临床验证。

## 剩余瓶颈与下一步

全量后另对相同 23 个重点帧采集 CPU 后处理剖析，排除导入、预热、网络、解码及导出；该回放也通过精确输出比较。记录在 `profile_v4/post_cpu.txt`、`hotspots.json`，驱动及 SHA256 单独保存。剖析有额外开销，以下数值用于定位，不代替正式视频耗时。

| 新版热点 | 每帧累计 ms | 关系 |
|---|---:|---|
| S2 expand | 26.46 | 包含 cap、证据、梯度等子调用 |
| ConnectedBlue grow | 16.37 | 包含主体识别及连接颜色区域 |
| S2 fit_cap | 9.96 | 17 次调用摊入 23 帧，已包含于 expand |
| G0 fit_geometry | 5.38 | 包含侧边观测和拟合 |
| G0 roi_tip | 2.56 | 上轮同一组选帧剖析约 8.38 ms，仅作机制对照 |
| 坐标缓存入口 | 0.03 | 81 次查找的总摊销，没有重复创建完整网格 |
| 全部 lstsq | 1.50 | 单独改写仍不足以解决剩余预算 |

累计值相互嵌套，不能相加。完整视频中，**S2 已占 CPU 后处理的 85.8%**。当前应把优化重点转到 S2；继续只缩短 G0 的收益空间较小。

下一步优先级：

1. **S2 坐标域及候选处理的保守 ROI**。先从主体像素的原顺序、原逐点算式得到轴向范围和法向分位数，再界定原搜索域；不能改变种子、量化顺序或用近似分位数代替。将域判断、候选提取、掩膜编辑等扫描融合，独立检查每个中间域及最终输出。该扩展尚未实现，不能沿用 G0 的倍数预测其收益。
2. **再融合 grow / expand / cap 的像素路径**。连通传播必须保留所有潜在可达像素；任何连通区域裁剪都要覆盖整个图中的有效图和 anchor。梯度需真实原图邻域，距离变换需完整相关边界，不能直接把本轮 1 像素 halo 规则套给这些算子。先测含所有准备和回传成本的原生编译或 GPU 原型，再做完整回放。
3. **本轮新版另行验证流水**。当前实验没有给出 v4 流水 FPS。网络仍有设备同步，迁移算子到 GPU 可能改变原先的 CPU/GPU 重叠；应使用配对完整实验测吞吐与延迟，再决定是否采用。

当前 CPU 平均 **57.41 ms**。仅将这一阶段压到 30 FPS 对应的约 33.33 ms，就需再减少 **41.94%**，网络与其他路径仍须另外满足预算。若要求单帧串行全路径低于 33.33 ms，还需把网络和全部额外成本计入。**ROI 已带来可验证收益，但本轮不能宣称实现 30 FPS。**
