# G0 第七轮独立优化：色度复用与 NumPy 坐标广播

2026-11-06。第七轮组合候选通过完整对照：同轮合并吞吐 **11.22 → 12.70 FPS（+13.21%）**，CPU 后处理 **59.20 → 50.29 ms/帧（−15.05%）**；2,694 帧 S2/G0 零像素变化，60 项检查通过。完整计时受运行条件影响，下文另用固定输入交替复测判断 CPU 净收益；仍未实现 30 FPS。

从第六轮纯 NumPy 候选 v6 继续，恢复后的 v4 入口及前六轮代码均保持原样。`final/` 全程不读取、不运行、不修改，不启用自定义 DLL，不安装依赖。

## 实现范围

当前帧色度复用：原 `grow` 先取 `frame[region]`，颜色判断再归一化；随后 S2/G0 还会使用整帧色度。新候选先取得同一帧的色度/噪声缓存，再以同一 region 行序提取，送入原大数组颜色公式。float32 加法分组、噪声、背景距离及阈值保持原式。缓存仍在每次 `run` 开始时失效，不按图像对象地址跨帧复用。

小于 4096 个像素的区域、浮点图像和不是当前运行帧的调用继续使用原颜色函数。小 RGB 探针、弱历史种子和端帽终端计算规则不改。

坐标广播：初始生长和端帽共享准备分别使用只读绝对坐标网格的 `H×1` / `1×W` 视图，减少二维减法和乘法临时数组。最终投影仍是完整尺寸，不裁剪生长图、端帽外围、梯度或距离变换。代理仅绑定到两个实例私有函数的 globals；没有修改全局 NumPy。

保留原模型、FP32、每帧双网络、PIL 输入、阈值、精确分位数、拟合迭代和帧序。两项修改可通过 Runtime 的 reuse / broadcast 开关分别启用；组合候选不替换 v4 恢复入口。

## 语义检查和消融

60 项检查通过。新增检查逐值比较色度、噪声和颜色判据，覆盖随机/黑/白/蓝图像、float32/float64 种子、normal/weak 两种阈值、4095/4096 边界及空区域；检查广播后的每个投影值、只读性、实例隔离、原全局 NumPy 不变。状态序列覆盖断裂、结石、无主体、面积预算回退、重置与复用同一个被修改的图像缓冲区；三种开关配置均与 v6 的 S2/G0、生长层、端帽、几何和输入不变性一致。

使用 video_2 的 23 个重点帧，固定原图、Raw2 与概率在内存，输入哈希与历史完整回放一致。每轮四方案各预热 12 次后重置状态，每帧旋转方案顺序，并在轮间反转；只计 CPU 后处理，排除网络、解码、审计及导出。三轮共 207 对候选/基线输出比较全部通过。

## 完整测量设计

两段视频共 722 / 1,972 帧，同轮 v6-serial 对组合 v7-serial。独立进程、CPU 库单线程，12 次预热后重置；video_1 顺序 v6→v7，video_2 反序。沿用第六轮无损审计位打包，批量 PNG/日志导出延后；墙钟吞吐包含解码、同步网络、CPU 后处理和轻量审计。单帧结果延迟在审计打包前结束，不含摄像头、显示、编码或处理前排队。

保留 Raw2、概率、S2/G0 哈希和解包后的逐帧 PNG 比较，同时核对 G0 决策/几何（1e-9）、历史 S2、结石标签、模型状态、双网络前向次数、视频及源码身份。颜色缓存命中次数会因预先创建整帧缓存而增加；其余种子、证据、候选及探针计数应与 v6 一致。

首次完整启动在源码归档清单中遇到路径拼接错误，四案例均在预热/正式计时之前停止，未生成性能结论。日志保存在 `full/`。仅修正测量脚本，实际重放 23 帧与历史 v6 输出一致后，完整对照另存到 **`full_fixed/`**。消融时的运行算法与正式版相同，消融归档中的 benchmark/run_full 脚本为修正前版本；两份身份分别保留。

## 完整实验后的固定输入复测

另在同一进程内用 v6 / 组合 v7 两个实例重放相同 23 个重点帧，做四轮交替配对。每轮各预热 12 次后重置，每帧改变先后顺序。原图、Raw2、概率固定在内存，哈希与正式完整运行一致；仅计后处理，不包含网络、解码、审计和导出。

| 1 | 54.1044 | 48.4036 | 10.54% |
| 2 | 54.8114 | 48.6363 | 11.27% |

## 新热点与下一步判断

正式回放中，S2 仍占 CPU 后处理 **82.71%**。另采集了 23 个重点帧的纯后处理剖析，包含剖析开销，平均约 59.5 ms/帧；其输出再次与历史 v6 精确比较通过。

| 范围 | 每个剖析帧累计 ms | 关系 |
| --- | ---: | --- |
| S2 expand | 18.6 | 包含证据、梯度和端帽 |
| 初始 grow | 15.1 | 包含种子提取与区域颜色判断 |
| S2 fit_cap | 9.1 | 17 次调用摊入 23 帧 |
| 初始种子提取 | 6.3 | 已包含在 grow 中 |
| region_color | 5.2 | 包含提前创建整帧色度和区域选择 |
| 分组剖面 | 4.5 | 40 次调用，分布在两条父路径 |
| 完整梯度 | 2.9 | 保留完整真实图像邻域 |

累计值相互包含，不能相加。新剖析中色度实际计算 23 次，上一轮相同帧为 46 次，说明重复归一化被消除。证据函数现在命中更早创建的色度缓存，部分耗时只是移到了 grow，不能只根据证据函数计时下降推断净收益；净判断以完整后处理与上述配对为准。

后续优先级：

1. **先测 v7 的有界网络/后处理流水线。** 目前多轮 NumPy 局部修改已获得改善，实际实时帧率还应测网络与 CPU 的重叠。保持 S2/G0 在单线程按原帧序处理、原时间戳、每帧两网络前向和最多两帧在途，验证吞吐与单帧延迟，不能套用旧版流水数据。本轮没有 v7 流水实测。
2. **再减少同一不可变主体上的重复坐标与统计扫描。** 剖析仍有 796 次 nonzero，合计约 4.0 ms/帧，分组剖面约 4.5 ms/帧；可在单次调用作用域传递同一掩膜的行序坐标，保持各调用原有投影算式和排序。主体/候选修改后立即失效，不能按对象地址跨帧缓存，也不能用逐点乘加替换原矩阵投影后假定浮点完全相同。这些全局时间分散在不同路径中，不是可全部消除的预算。
3. **继续保留精度与图结构约束。** 全部小矩阵 lstsq 约 1.6 ms/帧；减少拟合轮数、近似分位数、跳帧、裁连通图或直接缩小梯度/距离变换会改变合同，暂不作为等价提速方案。

按本轮 CPU 后处理 50.29 ms 估算，即使与网络理想重叠、没有额外争用，CPU 阶段也只允许约 **19.88 FPS**。这是条件性容量估算，不是流水线实测，单帧延迟也不会等于两阶段耗时的最大值。30 FPS 需要 CPU 阶段至少再下降 **33.72%**，并另留调度、解码、审计和波动余量；当前网络 P95 也超过 33.33 ms。

结论：保留 v7 作为纯 NumPy 独立实验候选，下一轮优先实测流水线；恢复后的 v4 入口不替换，`final/` 不迁移，不重新启用自定义 DLL。

